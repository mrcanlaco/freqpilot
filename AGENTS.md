# FreqPilot
User goal: evolve the existing Freqtrade setup toward RoboQuant's strategy-centered workflow, reusing FreqUI Ultimate and official Freqtrade features first. Keep official Freqtrade 2026.9 engine unchanged.
Only backtesting and paper trading on Binance Futures isolated at 1x are authorized. Never set dry_run=false, add trading keys, auto-optimize, or replace the paper strategy silently.
The current installation's runtime data/config/databases stay outside this repo in ../freqtrade/user_data. New independent installs may use the ignored runtime/user_data or an explicit external path. Never commit runtime files or credentials. Initialize must never overwrite existing env/data, and Start/Stop must verify existing project mounts before acting. Check.ps1 uses private scratch data and never starts trading services. Ultimate comparison stays separate in ../freqtrade-ultimate-compare.
Direct execution state is a UI-owned BotRow extension in datasource/execution.ts, separate from connection status. Use native show_config.state with its own observation age; never infer RUNNING from Online, /status or max_open_trades. Invalidate execution evidence after a write and confirm through a new native config read. Research worker lifecycle goes through the verified profile API on the /paper page; generic Direct start/pause/stop/reload controls must not bypass it. Do not modify generated Gateway types to imply unsupported execution evidence.
UI is a GPL-3.0 derivative of FreqUI Ultimate v2.1.0; preserve notices. Reuse native stores, API, charts, reports, and Monaco. Backend extensions may manage research files but must not replace engine modules.
Maintain evidence of feature status and comparisons. Do not present planned AI, tick/L2 fills, validation or deployment features as implemented. User has requested 5–10 existing strategies be backtested and compared after development; use a common frozen protocol, record provenance and compatibility changes, no parameter tuning.

Research paper service: research-paper / localhost:8095, separate from the existing paper bot 8090. Use native RPC start/pause/reload_config, no Docker socket. Profiles come only from verified backtest artifacts; original signals and parameter values are retained, with a 1x wrapper. Do not edit prepared profile config or sources in place. Never switch profiles with open positions; preserve each profile database. Restart restores PAUSED if positions are open, otherwise STOPPED; no automatic new entries.

Named presets use native get_strategy and HyperoptTools.export_params; discovery imports the selected user strategy, it is not a sandbox. Only inspect while no native research job runs. Presets live outside Git in user_data/freqpilot/presets, are immutable and bind source revision/schema. Never overwrite the library .py/.json to apply a preset. Backtests and analyses get private code/parameter copies; native result ZIP parameter bytes must match the frozen input. Keep selected preset identity visible in reports, checks and paper profiles. Do not silently fall back to source defaults on a stale/missing preset. No automatic optimization.

Archive reruns use checked_bundle and the shared native launch_snapshot. Copy inputs from the verified archive, never loose snapshot files, current library/data, environment overrides or current service trading settings. Use a new run ID/output/package; preserve the parent. Review binds the exact archive hash. Compare all native trade fields (including orders), list order and the documented summary fields without rounding; nonfinite/missing comparison values remain unavailable. A successful rerun is still retained if parent comparison becomes unavailable. This is research replay, never the fork's database-seeding replay. Binance market metadata is not frozen in old packages; do not claim universal reproducibility. Keep accepted-job ownership bound to the research server even when its report panel unmounts.

Paper history belongs to its own history.sqlite, never the native trade databases. Persist only an allowlist of lifecycle facts; never native credentials, tokens, raw worker responses or exception bodies. A request/HTTP success is not execution evidence. Confirm desired state/profile only from a fresh native result; preserve uncertainty and observation gaps, never infer STOPPED from loss of contact or reconstruct old sessions/P&L. Serialize status observations with paper actions using paper_lock. Journal failure before start blocks that new activation; it must not block pause/stop, erase a confirmed native outcome, or cause automatic retries. No real lifecycle action is needed merely to verify history UI; use mocks for transitions and read the current native state for deployment proof.
